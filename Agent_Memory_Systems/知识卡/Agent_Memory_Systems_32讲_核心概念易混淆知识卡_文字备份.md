# 智能体记忆系统｜32讲核心概念与易混淆知识卡

> 24组关键概念对照。主线：保存≠可检索≠正确利用≠成功执行。
> 仅用于32讲课程的结课理论复习，所有D01—D30均为虚构教学案例。

## 全局记忆循环

观察事件 → 提取候选 → 维护有效状态 → 检索证据 → 模型理解与规划 → 控制器执行与核验 → 反馈写入

## 01. 模型参数知识 ≠ 外部记忆
- 相关讲次：第01—03讲
- 概念区分：模型参数是训练后保留在权重中的统计规律；外部记忆是运行中可写入、检索、修订的记录。
- 容易混淆：模型会回答某项通用技术，并不等于它记住了昨日这项科研任务的最新决定。
- 案例：昨天研究者决定暂停P项目收费调用；不应期待模型仅靠参数知道。
- 一句话记忆：跨会话的具体状态需要可持续的外部记录与核验。

## 02. 当前上下文 ≠ 聊天记录
- 相关讲次：第02—03讲
- 概念区分：上下文是本轮实际送给模型看的Token；聊天记录是应用保存的历史事件。
- 容易混淆：历史页面上看得到一句话，并不代表当前LLM请求包含这句话。
- 案例：30天前的决策仍在聊天日志中，但未被装入本轮上下文。
- 一句话记忆：保存、检索、装入上下文是三个操作。

## 03. 知识库 / RAG ≠ 智能体记忆
- 相关讲次：第03、08讲
- 概念区分：知识库是可查询的信息集合；RAG是“检索后辅助生成”的流程；Agent记忆还要管理个人/任务经历的写入、更新与过期。
- 容易混淆：接入向量知识库或RAG，并不自动拥有持续可靠的长期记忆。
- 案例：搜索论文是RAG；核对旧提议已被用户否决，涉及时间、来源与记忆状态。
- 一句话记忆：RAG可以是记忆系统的读取部件，不是完整生命周期。

## 04. 工作记忆 ≠ 短期记忆
- 相关讲次：第10讲
- 概念区分：工作记忆按功能定义：当前任务正在操作的信息；短期记忆按保留时长定义。
- 容易混淆：把某些资料放在短时缓存中，并不一定意味着它正被当前任务主动使用。
- 案例：当前目标、分解步骤属于工作记忆；短暂保存但未用到的对话片段不必是。
- 一句话记忆：功能分类和时间分类是不同的坐标轴。

## 05. 情景记忆 ≠ 语义记忆
- 相关讲次：第10、11、15讲
- 概念区分：情景记忆记“某次经历发生了什么”；语义记忆记“经核验、可跨事件复用的事实与关系”。
- 容易混淆：一次工具失败的记录，不能直接抽象为“这种工具总是失败”。
- 案例：D09发生504属于情景；经多次证据分析才总结出的接口限制属于语义。
- 一句话记忆：从事件到知识需要抽象、来源和核验。

## 06. 程序性记忆 ≠ 已掌握技能 / 执行许可
- 相关讲次：第10、24、26讲
- 概念区分：程序性记忆可保存“如何做”的步骤或经验；真正技能要在环境中验证，执行权限另由控制器检查。
- 容易混淆：记住一份“调用API的操作步骤”，不等于获得经费批准或调用成功。
- 案例：科研助手有排障SOP，但P项目暂停付费时不得因此执行收费请求。
- 一句话记忆：知道步骤、能做成、获准做，是三种不同判断。

## 07. 记忆条目 ≠ 数据库存储 ≠ 搜索索引
- 相关讲次：第09、17、20讲
- 概念区分：记忆条目表达事实/事件/状态；数据库保存记录；索引（向量、全文、图）是方便找到记录的派生视图。
- 容易混淆：向量相似搜索得到一条记录，不代表它的索引副本是权威状态。
- 案例：关系库已更新“暂停”，向量索引暂未刷新，仍可能搜到过时的“可调用”。
- 一句话记忆：权威状态和可检索视图的责任要分开。

## 08. Embedding ≠ Q/K/V ≠ KV Cache
- 相关讲次：第05—07讲
- 概念区分：Embedding将内容映射为可比较的向量；Q/K/V是Transformer注意力计算中的投影；KV Cache缓存生成中复用的内部状态。
- 容易混淆：KV Cache不是跨会话、可独立维护的长期情景记忆库。
- 案例：向量库用Embedding找语义近邻；模型内部用Q/K/V处理已装入的上下文。
- 一句话记忆：这三者都含向量，却处于不同的计算环节。

## 09. 语义相似 ≠ 事实正确 / 当前有效
- 相关讲次：第07、14、18讲
- 概念区分：余弦相似度衡量向量方向接近程度，不核实主张真假、否定词、时间范围或授权状态。
- 容易混淆：“建议做实验”和“禁止做实验”可能语义相关，却在操作意义上相反。
- 案例：检索出旧的高相似付费建议，仍要查当前项目、时间与批准者。
- 一句话记忆：相关性排名之后，还要回源和做状态检查。

## 10. 触发检索 ≠ 找回候选 ≠ 正确利用
- 相关讲次：第21—24讲
- 概念区分：触发是决定“要不要查”；召回是“查到什么”；排序/选择是“给模型看哪些”；利用是“模型如何推理”。
- 容易混淆：只要检索Top-5中有正确记录，最终答案也可能用错。
- 案例：检索到D12暂停，但模型仍执行D04旧提议，是利用/控制问题，不一定是召回问题。
- 一句话记忆：故障定位要沿整条流水线拆开。

## 11. Flat精确搜索 ≠ HNSW / IVF / PQ
- 相关讲次：第18讲
- 概念区分：Flat逐个比对向量，通常是精确基线；HNSW通过分层邻居图加速；IVF先找分区；PQ用码本压缩向量。
- 容易混淆：更小或更快的索引，不保证得到正确历史事实；PQ压缩率也不等于整个数据库压缩率。
- 案例：百万向量搜索可用ANN减少候选，但重要权威决定还得回源核验。
- 一句话记忆：召回、时延、占用与维护是可比较的不同维度。

## 12. Precision@K ≠ Recall@K ≠ 任务成功率
- 相关讲次：第22—24、31讲
- 概念区分：Precision@K问取回的K条里有多少相关；Recall@K问全部相关证据取回多少；任务成功衡量最后行动是否达标。
- 容易混淆：检索10条中8条相关（高Precision），但漏了唯一“最新暂停”证据，也可能失败。
- 案例：模型找到证据却未核实执行结果，检索分数再好也不是最终任务完成。
- 一句话记忆：检索、问答、工具与环境要分别度量。

## 13. 原始事件 ≠ 候选主张 ≠ 当前状态
- 相关讲次：第11、14、16讲
- 概念区分：事件保存“谁在何时说/做了什么”；候选主张是从事件中提取的断言；当前状态是经过范围和时间核验后的有效视图。
- 容易混淆：记录“AI建议扩样”的真实事件，不代表“扩样已获批准”是真的。
- 案例：D04是AI提议；D12用户暂停才决定P当前授权状态。
- 一句话记忆：事件可为真，事件中表达的主张仍可能未经证实。

## 14. 事件时间 ≠ 有效时间 ≠ 系统获知时间
- 相关讲次：第14、30讲
- 概念区分：事件时间是活动发生时；有效时间是事实对业务生效的时段；系统获知时间是记录被系统接收的时刻。
- 容易混淆：D14才录入，不代表D12才生效的决定自动改成D14生效。
- 案例：D12用户暂停P，D14系统读取记录；问“D13当时生效什么”和“D13系统已知什么”答案可不同。
- 一句话记忆：理解历史需要双时间甚至多时间视角。

## 15. 有来源 ≠ 可信 ≠ 获得授权
- 相关讲次：第16、24讲
- 概念区分：来源追溯表示证据从哪里来；可信度表示支持程度；权限决定某主体能否执行某项操作。
- 容易混淆：三个Agent重复引用同一博客，不是三份独立证据；真实论文也不构成用户付费授权。
- 案例：来源可查的旧决策仍可能过期；高可信的操作方法也可能未经批准。
- 一句话记忆：出处、真伪、适用范围和执行许可分开核验。

## 16. 新增 ≠ 合并 ≠ 更正 ≠ 失效
- 相关讲次：第14—15、25讲
- 概念区分：新增是新事实；合并处理重复/相关记录；更正修复过去的错误；失效标记过去正确、现在不再有效。
- 容易混淆：把旧错误覆盖成新版本，会丢掉“系统曾误知什么”的关键证据。
- 案例：过去允许、现在禁止属于状态变化；过去记录写错则是对历史认识的更正。
- 一句话记忆：新旧关系和版本应保留，不能静默覆盖。

## 17. 检索降权 ≠ 业务遗忘 ≠ 物理删除
- 相关讲次：第25讲
- 概念区分：降权只改变搜索排序；业务失效令信息不再作为当前事实；物理删除还涉及原文、索引、缓存和备份策略。
- 容易混淆：按遗忘曲线降低一条信息的权重，不会让法律/预算/安全约束自动失效。
- 案例：旧的“暂停付费”决定即使很久不被提起，也不能仅因时间久而失效。
- 一句话记忆：删除必须明确作用域和副本传播，不能靠降低相似度冒充。

## 18. 摘要压缩 ≠ 记忆巩固 ≠ 原文历史
- 相关讲次：第13、15讲
- 概念区分：摘要以较少Token表达内容；巩固把相关经历整合为知识；原文历史保留可核对的事件与来源。
- 容易混淆：“未批准的建议”被摘要成“批准方案”，即使摘要简洁也变成了记忆污染。
- 案例：D09日志→D18原因核验→故障诊断经验：每一步都要留来源与版本。
- 一句话记忆：重要否定、时间、数字与证据指针优先保真。

## 19. 当前上下文 ≠ Checkpoint ≠ 长期记忆
- 相关讲次：第04、20、28讲
- 概念区分：当前上下文供模型本轮阅读；Checkpoint保留某条任务线程的运行状态用于恢复；长期记忆保存跨任务可复用的信息。
- 容易混淆：线程恢复成功，不代表下一段新对话会自动知道该项目所有历史。
- 案例：运行中断后继续步骤靠检查点；跨月保留项目结论靠长期记忆。
- 一句话记忆：两者可协同，但存储用途不同。

## 20. 权威状态 ≠ 派生索引 ≠ 缓存
- 相关讲次：第09、20、25讲
- 概念区分：权威状态用于回答当前有效业务结论；索引用于快速找候选；缓存用于减少重复读取延迟。
- 容易混淆：缓存命中不保证最新，索引未同步不代表权威状态未更新。
- 案例：数据库v12已更新暂停，向量索引v10仍指旧提议；关键决策回权威数据核对。
- 一句话记忆：检索速度和状态一致性需要分别设计。

## 21. 功能 / 时长 / 表示 / 归属：四条轴
- 相关讲次：第10、17、20、32讲
- 概念区分：功能：工作/情景/语义/程序；时长：临时/长期；表示：文本/结构化/向量/图；归属：用户/线程/项目/共享。
- 容易混淆：不能说“向量记忆是第五种功能记忆”，也不能说“一种功能必须配一种数据库”。
- 案例：一条长期情景记忆可用文本保存，也可建立向量索引并归入某个项目。
- 一句话记忆：多维分类可组合，不能混成一张互斥分类表。

## 22. 模型规划 ≠ 工具调用 ≠ 环境完成
- 相关讲次：第04、24讲
- 概念区分：规划是提出步骤；工具调用要经过参数/权限校验并实际派发；环境完成由独立结果或权威状态核验。
- 容易混淆：模型文字中写“我已执行”，不等于工具有调用Trace或目标已经达成。
- 案例：API返回HTTP 200不一定等于业务完成；504也不必然等于下游完全没执行。
- 一句话记忆：建议、实际执行和成功验收都要有独立证据。

## 23. 记忆失败 ≠ 推理失败 ≠ 工具 / 评分失败
- 相关讲次：第24、31—32讲
- 概念区分：遗漏正确记录是召回问题；已读到却误解是模型利用问题；错误参数、环境故障或Gold/评分错误属于不同责任层。
- 容易混淆：不能把所有Agent失败笼统解释成“记忆系统不可靠”。
- 案例：最新暂停已在输入中，但代理越权调用：调查控制器，而非只增加检索条数。
- 一句话记忆：先定位故障层，再讨论改进方法。

## 24. 更多记忆 / 更复杂架构 ≠ 更高可靠性
- 相关讲次：第20、26、31—32讲
- 概念区分：长期性能取决于写入质量、检索、时间有效性、推理行动与成本；多余记忆可能增加冲突、延迟和误用风险。
- 容易混淆：多加一个向量库或图数据库不是天然科研创新，也不保证任务成功率提高。
- 案例：简单项目状态表能解决的问题，不必默认升级为完整图记忆架构。
- 一句话记忆：以真实任务效果、成本、失败边界评估架构增量。

## 结课独立重建：六个判断门槛

1. 来源是什么：原始事件、用户决定、AI建议还是派生摘要？
2. 时间是什么：事件何时发生、何时生效、系统何时得知？
3. 作用域是什么：对应哪个用户、项目、线程，是否有例外？
4. 证据如何核验：源材料在哪里，有多少独立上游来源？
5. 故障在哪里：写入、检索、理解、计划、控制器、环境还是评测？
6. 增加复杂度是否值得：任务可靠性、质量、成本有没有可证据化的提升？

## 推荐自检的10个问题

1. 聊天记录保存了一件事，模型当前必然能用它吗？
2. RAG和Agent长期记忆系统是不是一个东西？
3. 工作记忆和短期记忆为什么不是同一维度？
4. 情景记忆如何变成语义记忆？中间必须检查什么？
5. Embedding、Q/K/V、KV Cache各处在什么计算环节？
6. 检索相关度0.95为什么不表示95%的真实性？
7. 事实的生效时间和系统获知时间为何不同？
8. 删除、失效、检索降权有何区别？
9. 检索到正确依据，任务为什么还可能失败？
10. 多加一个图数据库是不是就一定提高科研价值？
