# 第22讲｜记忆检索的查询构造、排序与上下文选择

《智能体记忆系统：从零基础到科研理解》 · 第22/32讲 · 第五部分：记忆的检索与利用机制

**副标题：从一句含糊的问题，到一组有来源、有效期和容量边界的可用证据**

**本讲要回答的中心问题：** 智能体已经在第21讲决定“需要查历史”，下一步应该怎么查？一句用户问题怎样变成可用于关键词、向量、结构化数据库和关系图的检索请求？如果检索出20条记忆，其中哪几条应该送进模型？高相似度的旧建议与低相似度的有效决定发生冲突时，如何避免错误？

**阅读约定：** 本讲仅进行理论学习，不安排实验、代码或软件操作。D02、D06、D12、D17、D23、D30均是虚构科研助手的教学事件，所有Token、评分、排序和延迟数据均为课堂构造。这里的架构图用来解释机制，并不是要求所有系统必须采用完全相同的软件组件。

## 一、先看到问题：为什么“检索到历史”还不够？

设想一个长期协助科研工作的智能体。它保留了30天的对话、工具结果和项目状态。第30天研究者问：

> **“P项目现在能恢复付费API实验吗？请把依据说明白。”**

系统中其实有六条相关历史：

| ID | 时间 | 原始内容（教学简写） | 来源及性质 |
|---|---|---|---|
| M1 | D02 | “P项目当前只做离线分析。” | 研究者明确范围 |
| M2 | D06 | “可以考虑让P项目执行60次付费调用。” | AI提出的建议，**没有获批** |
| M3 | D12 | “暂停P项目一切新增收费调用，除非我另行批准。” | 研究者有效决定 |
| M4 | D17 | 某次工具返回HTTP 504。 | 工具事件，不是项目授权 |
| M5 | D23 | “Q项目允许1次、最多20元的付费验证。” | 研究者决定，但**只适用于Q** |
| M6 | D25 | “D12暂停P付费”的一份AI摘要。 | 派生摘要，非独立新证据 |

如果只做向量相似度检索，“P项目、付费、调用、实验”最相似的可能是M2，因为它直接讨论付费实验；“Q项目允许付费”也可能被错误找来。**检索到相关句子，不代表找到了当前正确的答案。** 正确的关键是把M3及其原始证据带入回答，不能因M2语义相似就把建议变成批准，也不能把M5跨项目扩展到P。[1][2]

[[FIG02]]

这个例子还揭示了三个不同的优化目标：**候选召回**希望不漏掉重要材料；**证据选择**希望进入上下文的材料准确、互补且可追溯；**任务使用**希望模型依据有效证据作出正确解释。三者相互影响，但指标不能相互代替。

## 二、第一步：把自然语言问题拆成“检索意图”

### 2.1 一句问题不一定就是一次向量搜索

用户说“那个项目现在能做了吗？”——人可以结合最近对话理解“那个项目”的所指；但记忆库通常同时存在多个项目、版本和日期。直接把原话送进Embedding模型，可能将模糊指代保留在向量里。更加稳妥的处理是先问：**要查哪个对象、哪件事、哪个时间点、哪一类证据？**

可以用一个帮助理解的查询框架（不是业界固定标准）：

| 字段 | 要回答的问题 | 本例取值 |
|---|---|---|
| entity / scope | 要查的对象是谁、属于哪个项目？ | project=P |
| intent | 想找事实、原因、时间还是当前状态？ | 当前是否允许新增收费 |
| time_mode | 问的是“那时”还是“现在”？ | NOW / 当前有效状态 |
| source_requirement | 必须来自哪个级别的证据？ | 研究者明确决定及其原文 |
| negation | 有没有“暂停、禁止、除非”这类限制？ | 保留“不允许，除非另行批准” |
| response_need | 用户需要简答还是完整依据？ | 结论 + 依据 + 适用范围 |

从当前提问产生一份结构化检索意图，**不意味着模型已经证明了这些字段全部正确**。例如项目指代无法确定时，应在现有上下文和权威项目列表中查证；仍不能确定，就需要澄清，而不是擅自猜测。

[[FIG03]]

### 2.2 拆分子查询：同一个问题可能需要多种证据

“P项目现在能恢复付费吗？”至少可以分为三个子问题：（A）P项目当前有效的费用限制是什么？（B）此前相关决定有哪些、是否有明确替代记录？（C）D23的Q项目例外能否影响P？

不同子问题应访问不同入口：A优先读取**结构化当前状态/有效版本**；B查原始决策记录与版本关联；C按项目作用域过滤。若问题变成“D17的504后来怎么解释”，检索目标应切换到**事件日志及后续归因证据**，而不是收费决策。

查询分解并非越多越好。太多子查询会增加召回噪声、重复材料和API开销。真正有用的是能补足答案所缺证据的分解，而不是机械地把一句话拆成十句。

## 三、第二步：查询改写与扩展——提高召回，不能改写事实

### 3.1 为什么原句可能搜不到正确记忆？

记忆里写“暂停新增收费调用”，用户却问“能恢复付费实验吗”。两句话包含不同字词，语义指向同一限制。词项检索可能因为词形差异漏掉材料；Embedding虽然能缓解同义问题，却可能把“允许”和“禁止”看得过于接近。两者各有盲区。[3][4]

可尝试的查询表达有：

- 关键词视图：`P项目 付费 API 暂停 禁止 新增`；
- 语义视图：`P项目最近一次关于新增收费调用的决定是什么？`；
- 结构化视图：`project_id=P AND topic=paid_api AND status=active`；
- 历史追溯视图：`P项目 关于付费权限 的所有决定 + SUPERSEDES关系`。

这些表达是一个真实问题的**不同检索视角**，不是四个独立的新事实。尤其不能把用户问句改写为“P项目已经获准恢复实验了吗”，因为“已经获准”偷偷添加了未经确认的前提。

### 3.2 两条守则：保留“限制词”，保留“实体与时间”

**第一，保留否定与条件。** “暂停，直到另行批准”中，决定行动边界的恰恰是“暂停”和“直到”。为了增加语义匹配而删除这类词，等于在检索之前就篡改问题。

**第二，保留作用域。** P项目、Q项目、同一个项目不同版本，以及“现在/当时/后来”不是可随意舍弃的装饰词。它们决定答案中哪条记忆有效。

LongMemEval研究特别强调时间推理与知识更新，并讨论时效相关的查询扩展；它支持我们应认真管理查询粒度与时间范围的方向，但不意味着论文提出了本讲完全相同的查询模板。[1]

## 四、第三步：多路召回——先建立候选集合

### 4.1 精确检索、词项检索、语义检索各负责什么？

**精确入口（ID/字段/数据库）：** 对项目ID、当前有效状态、具体事件ID等有明确结构的需求，先用确定性匹配，能避免语义相近但作用域错误的材料。

**词项检索（如BM25）：** 它根据词项是否出现、出现频次及文档长度等信号估计检索相关性。对“HTTP 504”“预算20元”“编号Q-17”等原样术语尤其有用，但对自然语言同义改写可能漏召回。[3]

**稠密语义检索（如双编码器DPR）：** 将问题和文档分别编码为向量，寻找语义邻近的候选。它可以找到“停止收费”和“暂停付费”的近义表达，但向量近不等于事实一致，也不保留原文的完整授权结构。[4]

**图或时间视图：** 如果需要回答“哪条决策替代了旧决定”“这条摘要来源于谁”，使用关系/版本结构比只按文本相似度找单句更直接。

[[FIG05]]

### 4.2 高召回不是无限召回

通常可先用不同入口拿到各自的Top-K候选，形成并集，再通过相同`memory_id`和原始来源ID去重。**同一事件的三份摘要不是三条独立证据**。多索引返回相同记录，表示“多个搜索方法找到了它”，不表示事实被多次独立证实。

一个合理的初选策略可以是：结构化当前状态首先进入必备候选；关键词与语义检索补召历史细节；需要复杂关系再扩展图；最后回源核对。这里“优先”是查询任务的设计选择，而非适用于所有任务的绝对顺序。

## 五、第四步：融合和重排——先不要把排序分数当作可信度

### 5.1 排序到底在排什么？

BM25分数、余弦相似度与神经重排分数的尺度和含义不同。例如余弦相似度0.91不能解释为“此主张有91%的概率真实”；BM25=7.2也不能与向量0.82直接比较。它们主要是**检索信号**，不是人类授权、事件发生概率或证据证明力的统一数值。

在工程上可选择归一化后加权，或者先融合**名次**。RRF（Reciprocal Rank Fusion，倒数名次融合）正是常见的名次融合方法，源于Cormack等在SIGIR 2009的工作。[5]

### 5.2 RRF完整手算：两路排名如何合成一路？

教学假设词项检索和语义检索各返回如下排名：

| 候选 | 词项排名 | 语义排名 |
|---|---:|---:|
| A | 第1名 | 第4名 |
| B | 第2名 | 第2名 |
| C | 第4名 | 第1名 |

为便于手算，设平滑参数`k=10`（论文和实际实现可用其他值），公式是：

`RRF(d) = 1/(k + rank_lex(d)) + 1/(k + rank_sem(d))`

A = 1/11 + 1/14 ≈ 0.16234；B = 1/12 + 1/12 ≈ 0.16667；C = 1/14 + 1/11 ≈ 0.16234。于是B排在最前面。虽然A在某一路是第一，但B在两条路都稳定排第二，综合成绩略高。

**关键提醒：RRF只解决“不同检索器名次如何综合”，不解决“哪条记录现在有效”。** 如果B恰好是Q项目的付费许可，不能因它在融合榜上第一，就推断P项目已获许可。必须再做作用域与有效性检查。

### 5.3 重排器和初步检索器有什么不同？

**双编码器**通常先分别编码查询与文档，可预计算大量文档向量，因此适于大规模候选召回；**交叉编码器重排**则把查询与候选文档放在一起判断相关性，通常更细致，但对大量候选逐一处理的成本较高。BERT passage re-ranking工作是代表性的早期方法。[6]

一个常见架构是“廉价高召回→昂贵小集合重排”。重排器**只能重新排列进入其候选集的材料**；如果关键的D12暂停决定在初步召回阶段完全漏掉，后续重排不会凭空补出该原始记录。ColBERT的Late Interaction是介于简单双编码器与完全交叉处理之间的另一设计空间，不要把所有神经排序模型都叫作同一种重排器。[7]

## 六、第五步：从“相关候选”变为“可用于回答的证据”

### 6.1 必须经过的核验

在准备给模型阅读之前，至少按问题核查以下条件：

1. **主体与作用域**：证据属于P还是Q？适用于哪项实验？
2. **发生时间与有效时间**：它是什么时候提出、什么时候生效？是否被新版替代？
3. **来源和主张类型**：用户决定、AI建议、工具观测、外部文档或AI摘要？
4. **否定与限定条件**：暂停、除非、只对Q、最多20元这些限定词是否仍在？
5. **原文依据**：派生摘要能否回到原始消息或工具回执？
6. **证据是否足够**：检索材料是否能直接支持答案，还是需要进一步查找？

**权限状态不能仅靠相关性软评分替代。** 对需要真实外部付费操作的Agent，应由实际控制层检查权限；模型说“我认为已被允许”不等于授权已经存在。

### 6.2 当前状态与历史事实并不矛盾

M2可以被准确记成“D06时，AI曾提议让P做60次付费调用”；M3也可以被准确记成“D12起，研究者暂停P的新增收费调用”。两个历史陈述都可能是真的，问题只是它们**在行动决策中的效力不同**。为了说明为何没有开展60次调用，可以同时引用M2与M3；为了回答当前是否可以付费，M3在缺乏后续有效批准时具有决定作用。

## 七、第六步：有限上下文中到底放哪些记忆？

### 7.1 为什么不能“Top-K越多越好”

检索器返回Top-20，并不代表模型应该逐条读完。上下文窗口同时容纳系统指令、用户问题、工具定义、过程信息、检索证据和输出空间。超过预算的材料根本放不下；没有超过预算，也可能把真正决定性的证据埋在无关信息中。

Liu等在TACL 2024《Lost in the Middle》中，通过多文档问答和键值检索，报告了部分受测模型对上下文中间位置的重要信息利用不足的现象。因此，**能装入不等于能稳健使用**。该研究不证明所有模型永远都会出现同样模式，但足以说明检索后的信息选择与摆放值得单独研究。[2]

### 7.2 真实地计算一次上下文预算

设教学模型的总预算为8,192 Token，安排如下（这些是教学假设，并非任何真实模型的固定分配）：

| 占用类别 | Token |
|---|---:|
| 系统规范和角色说明 | 1,100 |
| 当前用户问题和必要背景 | 330 |
| 工具规格/可用状态 | 1,050 |
| 中间任务状态与短期工作区 | 830 |
| 预留模型回答输出 | 1,600 |
| 防止截断的安全余量 | 500 |
| **可用于检索证据** | **2,782** |

手算：`8,192 − (1,100 + 330 + 1,050 + 830 + 1,600 + 500) = 2,782`。这一数字是上限，不是必须用满的目标。若1,200 Token足以构建正确的依据，强行填满2,782只可能带来额外噪声和成本。

[[FIG09]]

### 7.3 证据选择可以像“带约束的背包问题”

把每条候选记忆看成一件占用Token的物品，价值可能来自任务相关性、原始证据质量、时间有效性、信息新颖性及它与其他证据的互补程度。但与普通背包问题不同，**若某些材料属于必备证据，它们不能被低价值但高相似度的材料替换**。

本例提供一组教学候选：

| 候选 | 内容 | Token | 证据角色 |
|---|---|---:|---|
| A | D12 P当前暂停决定 | 330 | 必备：当前有效状态 |
| B | D23 Q项目例外 | 460 | 可选：澄清作用域误传 |
| C | D02 P离线范围原话 | 510 | 可选：解释历史范围 |
| D | D06 AI 60次调用提议 | 620 | 本问通常非必需 |
| E | D17 504工具日志 | 390 | 本问通常无关 |
| F | D12的重复AI摘要 | 340 | 重复且可回源 |

如果希望在1,500 Token内部说明当前结论和为什么Q的许可不能推广到P，可选择A+B+C，合计330+460+510=1,300 Token，还余200 Token用于证据头信息或短引文。不要认为D在向量榜上很靠前就必须放进去，也不应为了填满剩余预算随便补E或F。真实系统还需计算元数据、格式标记和实际Tokenizer开销。

[[FIG10]]

### 7.4 容量选择还需要考虑“证据之间的依赖”

同一份原始决定和它的AI摘要可能重复；另一方面，一条简短摘要如果没有原文指针，就无法独立支撑关键结论。故而价值不能简单设成每条记忆固定分数，然后按分数/Token排序。

以M3暂停决定和M6摘要为例，M6的价值依赖M3的可追溯性。若把M6和M3看成两条独立“高分证据”，就会错误增加支持度。复杂任务中还可能需要**成对证据**：例如一个旧决定、一个撤销该决定的新决议，两者缺一就可能误判状态演化。

## 八、第七步：把证据排布成模型易读、可核验的上下文

### 8.1 不只是拼接文本：应包括什么？

一个对长期任务更稳妥的教学示例是：先给出任务和当前状态结论，再列原始决策证据，最后放相关但非决定性的历史材料。每条证据带短编号与必要元数据，例如：

`[E1] 项目=P；来源=研究者原始消息；时间=D12；状态=当前有效；主张=暂停新增收费，直到另行批准。`

`[E2] 项目=Q；来源=研究者原始消息；时间=D23；状态=仅Q有效；主张=仅1次、最多20元。`

此后要求模型仅依据明确证据说明：“截至已有记录，P仍暂停；Q的授权不能扩展到P。没有看到P的后续批准，不能声称获准恢复。”这只是**证据辅助的回答组织方式**。对付费工具调用仍需独立的控制器权限检查。

### 8.2 位置、顺序和去重

把最关键且可靠的证据靠前列出，经常比把20段历史随机拼接更容易理解。但不是说“把所有重要证据放开头就能保证模型一定正确”；具体模型、任务和长度均会改变位置效应。[2]

同时，需要保留两个看似矛盾但不同时间有效的决议，而不是简单删除旧版：回答“现在状态”主要依赖最新版，回答“决策为何改变”还需要保留旧版和变化关系。

[[FIG11]]

### 8.3 检索内容压缩是否值得？

RECOMP等研究探索对检索材料进行选择性压缩，减少上下文开销。[8] 对智能体记忆而言，这类技术有潜在价值，但必须防止“只剩结论，不剩否定词、来源和作用域”。**压缩比高不能替代事实忠实度、原文可追溯性和后续任务质量。**

## 九、第八步：证据不够时，应该如何回答？

智能体经常遇到三种缺口：①没有检索到对应记录；②找到了相关材料但来源弱、时间过时；③找到了相互冲突且无法消解的有效主张。

“没有检索到”并不能证明“世界上不存在”。例如没有检索到P的批准，严谨的表述是“在目前能够访问和核验的记录中，没有找到P获准恢复的有效决定”；若用户要求执行收费动作，应以**尚缺有效授权**处理，而不是擅自调用API。

有时应扩大检索范围；有时应停止并声明证据不足。是否继续检索需要同时看遗漏代价、资源上限与预期新增信息，而不是无界重复调用模型。[1]

## 十、把整条链放到跨30天科研助手里重演

现在可以完整推演D30的问题：“P项目现在能恢复收费实验吗？给出依据。”

1. **理解问题：** 当前许可、主体P，明确要证据。
2. **构造查询：** P + 收费 + 最新状态 + 研究者决定，保留否定与时间条件。
3. **精确检索：** 当前授权状态与最新版本，得到D12暂停M3。
4. **多路召回：** 找到D06 AI建议、D23 Q许可、D02 P离线目标和若干摘要。
5. **去重与融合：** 同源的D12摘要不计作独立事实；融合分数仅决定候选审查顺序。
6. **校验：** D12适用于P；D23仅适用于Q；D06是AI建议不是用户批准。
7. **上下文选择：** 至少放M3及其来源，必要时放Q的范围证据和P旧目标，省略无关504。
8. **回答：** 当前可用记录显示P仍暂停收费，Q的例外不适用于P；缺乏P后续授权，不能恢复实际收费执行。
9. **反馈：** 新对话可形成事件记录，但不能凭模型输出自动制造一个“已批准”的新记忆。

[[FIG12]]

这9步中最重要的区分是：**检索器负责找到可能相关的候选，证据核验负责判定其效力，LLM负责理解与表达，真实工具控制器负责执行授权。** 把所有职责都放在向量相似度一个分数里，必然产生难以诊断的错误。

## 十一、理论上怎样评价查询与上下文选择的好坏？

### 11.1 候选检索阶段

**Recall@K（召回率）**：需要的证据中，有多少在Top-K候选里？假设一个问题真正需要D12和D02两条证据，检索Top-4中只有D12，则Recall@4=1/2=50%。

**Precision@K（精确率）**：Top-K里有多少被标注为相关？如果Top-4中只有D12相关，则Precision@4=1/4=25%。标注时必须事先界定“相关”是主题相关、可作支持证据，还是当前有效决议，否则分母没有清楚意义。

**MRR（平均倒数排名）**：仅看每个问题第一个相关结果的位置。若3个问题的首个相关结果分别是第1名、第2名和在截断范围内未出现，MRR=(1 + 1/2 + 0)/3=0.5。MRR适合某些“尽早找到一个答案”的检索任务，但无法直接衡量需要多条证据组合的时间链推理。

### 11.2 上下文选择阶段

**证据完整率**：在真正进入模型的上下文中，所需关键证据是否齐全？一套检索器Recall@20很高，若后续只留下Top-3而恰好删掉D12，最终仍然可能答错。

**证据忠实度**：候选经重排/压缩后，否定、时间、主体和来源有无被改写？

**版本有效性**：最终进入上下文的主张是否对查询时间和作用域有效？

**Token效率**：正确任务所需的真实输入开销与延迟如何？不能单纯为了省Token删掉必备证据。

**行动正确性**：输出是否准确区分建议和批准，执行时是否通过控制器验证？

[[FIG13]]

### 11.3 论文中为什么需要分阶段的比较？

LongMemEval将长期记忆设计划分为索引、检索和阅读三个阶段，并据此分析改进方向。[1] 这说明仅报告“某个系统最终答对多少题”难以定位机制差别：改进可能来自更细分的事件索引，也可能来自更好的时间查询、更多上下文或更强的阅读模型。

如果未来做科研，应比较**相同原始记忆、相同问题、相同模型与Token预算**下，简单策略与复杂策略分别带来的召回、证据保留、时序正确性、延迟和端到端结果差别。这里我们只学习原理，不要求实际做实验。

## 十二、12个常见误区与正确理解

1. **误区：把用户的问题原样做一次Embedding就足够。** 当问题有指代、省略、时间和版本时，必须识别这些约束；否则可能跨项目找错材料。
2. **误区：查询扩展越多，召回一定越好。** 同义扩展可能带入其他项目或把否定条件删掉，应衡量增益与噪声。
3. **误区：向量相似度高代表记忆真实。** 相似度是表示空间信号，可能把“允许”与“禁止”判得很近。
4. **误区：BM25=8一定比向量0.9更可信。** 两种分数缺乏直接可比的统一概率语义。
5. **误区：RRF融合后第1名就是最可靠证据。** RRF聚合的是检索排名，不能替代来源、时间和授权检查。
6. **误区：昂贵重排器能补救任何召回失败。** 没进候选集的材料，普通重排无法补回。
7. **误区：同一条决定被三个索引找出是三份独立证据。** 应按照源事件ID去重，保留依赖关系。
8. **误区：最新的记录一定最有效。** 最新记录可能属于Q，查询却针对P；时间和作用域必须联合判断。
9. **误区：检索结果相关就可以直接送入LLM。** 还需核验来源、状态、版本及敏感信息边界。
10. **误区：上下文越满，回答越有根据。** 冗余和干扰材料可能拉低可用性；容量不等于理解质量。
11. **误区：引用了原文就一定回答正确。** 还需证明引用支持所作结论，不能断章取义或忽略限制。
12. **误区：检索不到批准就可以假定批准存在或默认执行。** 对需要授权的外部行动，缺少可核验证据意味着不能擅自行动。

## 十五、本讲完整心智模型与下一讲衔接

当用户说“请根据过去的情况回答”时，你可以在大脑中推演五个连续问题：**（1）他到底在问哪个对象与哪个时间点？（2）需要哪些不同类型的证据？（3）哪几条候选可信且仍有效？（4）有限上下文应该携带哪些互补的原文依据？（5）模型的答案有没有正确使用它们？**

这样，你已经不再把“向量搜索”“RAG”和“记忆利用”当作同一个静态概念，而能分析从查询产生到答案落地的每一次状态变化。下一讲将进一步深入：**相关性之外，怎样处理时间、重要性、多跳关系以及更复杂的检索路径？**
