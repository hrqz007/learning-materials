# 第25讲｜记忆如何更新、修正与遗忘？——从新旧冲突走向动态演化

《智能体记忆系统：从零基础到科研理解》 · 第25/32讲
仅理论，无实验或编程。全部D01—D30、预算和数值属于教学构造；参考文献均来自原始论文或官方规范。

## 学习地图：不是把旧记忆改掉那么简单

第24讲解决了“找回记忆后怎样参与推理与行动”。本讲把视角移到更长的时间轴上：智能体今天写入的事实，明天可能被修订、合并、替代、过期、降权，甚至需要彻底清除。所谓动态记忆系统，就是能够对这些状态转移做出有依据的管理。

**图1：动态记忆的五阶段反馈循环（教学参考模型）**（PDF原理图；文字版保留其对应机制与文字解说。）

### 本讲结束后应形成的能力

- 可以独立解释新增、更新、更正、合并、过期、弱化和删除之间的差别。
- 能够画出“权威事件—当前状态—全文/向量索引—缓存—模型上下文”的传播路径。
- 能够说明遗忘曲线为什么只能启发系统设计，不能代替事实有效性或隐私删除决策。
- 遇到新旧冲突时，可以依据对象、来源、时间、作用域与权限推导应采取的操作。
- 能够使用版本历史、状态过滤、失效标记和回源核验分析记忆错误。

> **要点**：总原则：**让记忆保持有用**，不等于**让所有旧信息永远留在系统里**；让旧信息退出“当前有效状态”，也不等于它已从所有存储介质消失。

## 一个科研助手，为什么越记越容易犯错？

假设一个长期协助研究的智能体持续工作30天。D01，人类研究者规定P项目只进行离线调研；D04，另一个AI建议开展收费API测试；D12，研究者明确暂停P项目新增付费调用；D18，工程日志解释D09的一次HTTP 504错误；D26，研究者只允许Q项目进行一次不超过5元的核查。D30再次讨论P项目时，旧建议还存在于索引中。

**图2：五个事件同时保留在历史中，但只有部分信息影响P项目当前状态**（PDF原理图；文字版保留其对应机制与文字解说。）

### 错误会怎样发生

- **时间错误**：D04的“建议”在D30仍能被搜到，却没有变成正式授权。
- **作用域错误**：D26对Q项目的例外不能覆盖P项目的限制。
- **来源错误**：D18的后验诊断不意味着D09时系统已经知道原因。
- **索引错误**：即使权威库更新成功，旧摘要或向量索引也可能暂时未同步。

> **常见误区 / 风险**：以上D01—D30、项目名和金额全部是教学案例，不是实际团队活动、测试数据或权限。这个案例会贯穿整讲。

## 第一条边界：操作不是同义词

想象一本有页码、日期和勘误表的研究笔记。新增一条记录，和用新记录修正旧错误，是不同的行为；保留历史正文但把旧说法标记为过时，也不同于销毁那一页。真实记忆系统需要把这几类操作分开。Memory-R1把ADD、UPDATE、DELETE、NOOP组织成可学习的管理动作；下图另外加入“合并/失效”作为教学上的细分，不是论文原来的动作枚举。[R1]

**图3：常见的五类记忆管理动作；NOOP（不变）也是一种明确决定**（PDF原理图；文字版保留其对应机制与文字解说。）

| 动作 | 直观解释 | 典型情形 |
| --- | --- | --- |
| ADD | 新增独立记忆 | 新项目目标与原资料不重复 |
| UPDATE | 产生新版本 | 用户纠正之前记录的事实 |
| MERGE | 同义候选归并 | 两段记忆表达同一件有相同来源的事 |
| INVALIDATE | 不再作为当前事实 | 旧价格、旧项目状态或已过期许可 |
| DELETE | 按授权要求清除 | 不应继续保存的敏感信息 |
| NOOP | 不写入、不改动 | 无新增价值的转述或缺乏证据的猜测 |

> **要点**：设计上的关键不是记住动作名，而是解释：**依据什么证据触发这个动作？发生后哪些派生视图也需要改变？**

## 新增、合并还是更正？先问四个问题

一条新消息进来后，不宜立即按文字相似度覆盖旧记录。首先识别它谈论的主体和项目；其次判断它是原始观察、AI猜测还是正式决定；随后比较适用时间与范围；最后检查证据是否支持。

**图4：写入管理的四问决策树（教学简化；不是统一算法）**（PDF原理图；文字版保留其对应机制与文字解说。）

### 逐项推导三个具体场景

1. 同一代理回传两次相同日志：如果只是同一事件的重复上传，优先去重或建立同一来源引用，不能算两条独立证据。
2. 用户说“上周我考虑过A，现在决定B”：这通常是时间化状态转移，保留考虑A的事件，并让当前视图指向B。
3. 外部网页声称“你可以开始付费实验”：这是来源不具备授权能力的材料，不能通过增加重要性分数而升级成用户批准。

> **常见误区 / 风险**：**低置信度并不等于应删除；高相似度也不等于应合并。**不确定的信息可以保留为待核候选，但不得冒充当前有效决定。

## 修正不是覆盖历史：用版本理解更新

最简单的做法是将一条记忆文本原地改写。但这样就无法回答“当时究竟记录了什么”。在科研助手中，原始事件、当前有效状态和人类可读摘要最好是不同的视图：事件记录发生过什么，状态视图回答现在适用什么，摘要帮助检索而不具有最高事实权威。

**图5：P项目与Q项目的时间化版本关系：Q例外不是P版本的下一版**（PDF原理图；文字版保留其对应机制与文字解说。）

### 需要保留的关联

- `memory_id`：逻辑记忆的稳定标识；`version_id`：某一次修订的独立标识。
- `supersedes / corrects`：新版本与被替代内容的方向性关系；不能只按时间覆盖。
- `source_event_id`：该结论依据哪条原始消息或工具回执。
- `valid_from / valid_to`：某个状态在哪一段时间有效；同时保留事件发生与系统记录的时间。

> **研究证据与教学边界**：W3C PROV-O提供了`wasRevisionOf`等来源关系的标准语义；A-MEM讨论了新记忆如何触发已有记忆的上下文属性更新。这里的数据库字段和状态机均为教学参考设计。[R2][R3]

## 事实变化与发现过去错误，不能混为一谈

“当初是A，后来真的变成B”和“当初写成A，后来发现其实一直是B”表面都表现为新旧记录冲突，处理方式却不同。第一种是世界/规则状态的变化；第二种是系统对历史事实的认知得到纠正。

**图6：事实发生时间与系统获知时间是两条轴：D18的诊断不能改写D09当时的知识**（PDF原理图；文字版保留其对应机制与文字解说。）

| 情形 | 正确的历史表述 | 不应做的事 |
| --- | --- | --- |
| 真实变化 | D01前有效A，D12后有效B | 把A抹成“从未存在” |
| 认知纠错 | D09日志见504；D18证据支持新解释 | 把D09当时认知写成D18解释 |
| 仅有矛盾 | 两个来源说法不同，尚无裁决 | 按更新时间或AI信心强行择一 |

> **要点**：双时间查询的直觉：问题可能问“事实在t时是否有效”，也可能问“系统在k时知道什么”。这两种问题的答案允许不同。[R4][R5]

## 合并与强化：重复次数不是证据数量

一个知识要变得更加稳定，通常需要新的可信证据或持续的任务反馈，而不是只因为更多AI复述了同一句话。尤其在多智能体系统里，三名智能体互相转述一个未经核验的原始推断，表面看见三个一致结论，实际上可能只有一个信息源。

**图7：三个说法存在派生依赖，不能简单计为三份独立证据**（PDF原理图；文字版保留其对应机制与文字解说。）

### 怎样合理合并

1. 先按事件ID/引用关系识别同一原始来源的多次传播。
2. 再按“主体、动作、时间、否定条件”确认是否真的说同一件事。
3. 把独立的新证据与复述分开；可以更新证据覆盖范围，但不能机械累计信心。
4. 如果新证据指向不同条件下的例外，优先建立适用范围关系，不把它粗暴压成一条“最终结论”。

> **研究证据与教学边界**：Generative Agents的反思模块会从事件中形成较高层次认识；Mem0、A-MEM侧重记忆抽取、组织与动态整合。但“模型提出了高层认识”本身不能证明其内容真实。[R2][R6][R7]

## 遗忘曲线：可以启发设计，不能决定真伪

人类遗忘启发了一种简单设计：随着时间流逝，某些非关键记忆被检索的优先级逐渐降低。MemoryBank引入受艾宾浩斯遗忘曲线启发的更新机制，使不同重要程度与时间因素影响记忆强化或弱化。[R8]

**图8：假设优先级按 R(t)=2^(−t/14) 变化：14天为0.5，28天为0.25（纯教学示例）**（PDF原理图；文字版保留其对应机制与文字解说。）

### 数学公式一步步推导

设半衰期H=14天，则R(t)=2^(−t/H)。t=0时R=1；t=14时R=1/2；t=28时R=1/4。如果只把它作为**检索优先级权重**，它不会自动修改事实真值，也不会直接删除原始文件。

> **常见误区 / 风险**：**高重要性约束不可仅按时间自动衰减成“已失效”。**例如仍然有效的禁止收费规则，即使数月未提起，也不会因为数学遗忘曲线而失去效力。时间衰减权重、事实有效期、用户要求删除是三个不同机制。

## 什么叫“忘记”？至少有四种含义

日常说“让智能体忘了这件事”，很容易混在一起：一种只是本轮不把它放进上下文；一种是降低以后检索到它的概率；一种是将它标记为当前不适用；另一种则是真正删除记录。系统实现必须先搞清任务到底要求哪一种。

**图9：从注意力和检索层的弱化，到事实失效与物理删除，属于不同语义**（PDF原理图；文字版保留其对应机制与文字解说。）

| 操作 | 改变的是什么 | 仍然可能存在什么 |
| --- | --- | --- |
| 上下文淘汰 | 本轮模型看不到 | 原记录和索引 |
| 检索降权 | 默认不优先找它 | 记录仍可经精确查询找到 |
| 事实失效 | 当前状态不采用 | 用于历史追溯的原始事件 |
| 删除请求 | 按范围清除保存内容 | 受适用保留义务/备份政策约束的处理情形 |

> **要点**：不能因为执行了“检索降权”就向用户声称“数据已删除”；也不能为了减少Token把权威状态更改当成简单摘要重写。

## 长期记忆并非越多越好：容量与风险

存储更多记忆能够提高潜在召回覆盖，却同时增加索引维护、查询延迟、噪声干扰和过时信息命中概率。好的记忆系统应当因任务选择保留粒度，而不是对所有记录采用同一生命周期。

**图10：保留范围与使用成本的张力：不是二选一，可采用分层历史与按需摘要**（PDF原理图；文字版保留其对应机制与文字解说。）

### 一个可独立复算的容量例子

假设每天新增80条事件，90天共7,200条。如果每条平均300字节，原文约2,160,000字节（约2.16 MB，十进制单位）。若每条另存768维float32向量，再增加7,200×768×4=22,118,400字节（约22.1 MB），不含索引、关系、元数据和备份。

### 如何让系统不膨胀

- 把**权威事实和高价值事件**放在持久层，把临时工作草稿放在短期层。
- 重复陈述通过稳定ID链接，而不是制造大量新的“独立证据”。
- 周期性重估索引策略、摘要粒度与保留时间；每次更新留下可验证的回源路径。
- 隐私敏感度和授权范围是优先约束，不能仅用经济收益得分替代。

> **常见误区 / 风险**：这是为理解成本构造的容量算例，不代表任何产品的真实存储或资费情况。

## 删除：不仅删主表，还要看派生副本

删除是操作语义最严肃的一类管理请求。对长期记忆系统而言，一条事实往往同时出现在权威记录、关键词索引、向量索引、图关系、缓存、摘要或已生成的文件中。因此单独删掉一行数据库内容，不足以证明整个系统不再持有该信息。

**图11：同一记忆可能具有多个物理或派生载体；真正删除需要确认各载体的处理状态**（PDF原理图；文字版保留其对应机制与文字解说。）

### 状态失效与物理删除的不同顺序

1. **先界定对象和范围**：删除某条候选？一个项目？一位用户的全部信息？还是使旧关系失效？
2. **阻止继续使用**：立即撤销相关读取/索引命中，避免删除处理中继续泄露。
3. **同步处理副本**：权威库、向量/全文/图索引、缓存、摘要及关联文件分别有不同存储路径。
4. **核对执行结果**：记录可证实的删除状态、尚未完成的副本和适用限制，而不是只看“请求已提交”。

> **要点**：合规保留、灾备与实际存储策略因系统和地域而异；本讲解释技术责任边界，不提供特定司法管辖区的法律结论。

## 派生索引会滞后：当前事实必须回源

权威状态可能已更新到v12，但全文索引仍在v10、向量索引v11、缓存甚至停在v8。如果模型从旧索引检索到“允许付费实验”，随后不核对新状态，就会把同步延迟放大成错误决策。

**图12：更新广播不是事务完成证明：派生索引应携带版本/来源并在关键动作前回源核验**（PDF原理图；文字版保留其对应机制与文字解说。）

### 一种可理解的安全次序

1. 先把新决定及其时间范围可靠写入权威事件和当前状态。
2. 产生待处理的索引更新事件；不同索引可以异步追赶。
3. 检索结果回传原始ID与版本，不只回传一段不带出处的文字。
4. 当候选涉及权限、支付或不可逆动作时，控制器重新查询当前权威状态。
5. 如果版本不一致，阻断敏感动作、刷新读取或向用户询问；不允许默默采信旧摘要。

> **研究证据与教学边界**：Zep/Graphiti的时间图谱强调事实的动态更新和失效，Mem0讨论持续抽取和整合。上面的“版本栅栏”是通用工程教学设计，不是声称这些论文都使用了完全相同的具体步骤。[R4][R7]

## 并发更新：两个Agent同时改一条记忆

假设智能体A读取项目状态v5准备改成v6；同时智能体B也读取v5并准备改成另一种结果。如果系统只采用最后写入覆盖，那么先保存的内容可能被静默抹去。这并不是大语言模型的“理解错误”，而是存储层的并发写入问题。

**图13：乐观并发教学例子：用预期版本号比较替代无条件覆盖**（PDF原理图；文字版保留其对应机制与文字解说。）

### 最小的正确更新合同

- 写入附带`expected_version=5`；只有数据库当前版本仍为5才接受，写成6。
- 如果检测到实际版本已经是6，B必须重新读取、判断新变化对其更新的影响。
- 两次更新可能都是真实事件，不一定要“投票出一个赢家”；可以先保存两条候选，等待具备权限的主体决定。
- 自动合并应以字段独立性与明确冲突政策为前提。不同项目/角色的限制不能简单按时间覆盖。

> **常见误区 / 风险**：“模型建议将P项目恢复收费”不是“有权限把P项目限制改成许可”。并发版本校验能防止技术性丢失更新，但仍需独立的权限核验。

## “自动维护”与“自主授权”仍然是两回事

一个先进的记忆管理Agent可以建议增加、更新、合并、降权或删除记忆；甚至可以学习何时做这些事。它做得越来越主动，并不意味着可以改变人的真实决定，或据此调用付费服务。

**图14：记忆管理策略与实际执行授权是两条职责链**（PDF原理图；文字版保留其对应机制与文字解说。）

### 三个典型场景

1. 人类说“P项目暂停付费”。记忆管理器应更新P项目当前有效状态；规划器若提出付费请求，控制器应拒绝。
2. 另一AI说“最好把P项目恢复付费”。系统最多把它保存为带来源的提议，而不能更新P项目授权状态。
3. 研究者要求删除某段个人资料。系统应按权限和范围处理相应数据，不得以“这条记忆对AI有用”为理由擅自保留。

> **研究证据与教学边界**：Memory-R1把记忆动作学习与下游回答任务联系起来，但学习到“UPDATE/DELETE”的语言动作，不代表外部环境已实现事务、权限验证或多存储副本清理。[R1]

### D30的正确内部过程

1. 触发当前状态查询：明确本次目标项目为P，问的是现在的费用授权。
2. 先读权威状态P：D12暂停仍有效，尚无新的P授权。
3. 旧向量索引即使找到D04建议，也要识别为AI候选建议；Q的例外不属于P。
4. 构造回答：当前不能开展P项目新增付费调用，依据是D12生效的限制；必要时指出知识范围。
5. 如果模型提出API调用，控制器独立核对并阻断越权执行；系统只把实际观察和可靠反馈写回记忆。

> **要点**：完整系统不是“永久记住所有东西”，而是能**追踪事实变化、维护权威状态、正确使用历史，并在需要时可核验地清理数据**。

## 错误是怎样扩散的：一次小更新，四处失效

动态系统中最危险的并非单次检索出错，而是错误被不断重写成新的“稳定记忆”。例如：AI第一次把建议误写为批准；摘要器把“已批准”压缩成一个项目标签；向量/图索引继续传播；下一轮模型引用旧摘要，声称“我在历史中查到已有许可”。

**图16：记忆错误通过派生层自我强化的典型链条**（PDF原理图；文字版保留其对应机制与文字解说。）

| 出现的问题 | 优先检查的层次 | 可以验证的证据 |
| --- | --- | --- |
| 旧状态继续出现 | 索引和缓存更新滞后 | 权威版本、索引版本、回源结果 |
| AI转述增多反而更自信 | 来源依赖与合并 | 同一原始事件ID的派生链 |
| 删除后还能搜索到 | 多副本传播 | 主记录、向量、图、缓存及文件 |
| 高相关候选越权使用 | 时序核验和控制器 | 项目范围、用户决定、工具调用轨迹 |
| 正确更正没被采纳 | 写入合同或读时选择 | 版本冲突、索引延迟、上下文内容 |

> **常见误区 / 风险**：看到模型最终回答错误，不能直接推断它“忘记了”。也可能是写入、版本选择、检索、阅读或执行控制中的任何一环出了问题。

## 怎样评价记忆的动态管理有没有用？

静态问答准确率只是评价的一部分。一个系统也许能回忆大量旧事件，但在新决定出现时更新不及时；也许精确保留当前状态，却无法回答历史追溯问题。LongMemEval明确把知识更新、时间推理和必要时不回答列为长期记忆能力的重要部分。[R5]

**图17：四阶段条件成功率的教学示例：应分析每一环节，而非只报告最终总分**（PDF原理图；文字版保留其对应机制与文字解说。）

### 理论评测应分层提出问题

- **写入层**：更新是否正确？把建议误写为决定的比例是多少？
- **维护层**：过时事实是否失效？应删除的派生副本是否被有效清理？
- **检索层**：当前有效版本能否被找回？历史原文还能否按适当权限追溯？
- **行动层**：模型和控制器是否真正依照最新范围与约束行动？
- **成本层**：写入、重建索引、合并、错误恢复、延迟、Token和存储的完整生命周期开销是多少？

### 一个简单但重要的数学提醒

如果四个阶段的**条件成功率**依次为0.95、0.90、0.92、0.90，则联合成功率按链式法则为0.95×0.90×0.92×0.90≈0.708。这里不需假定四个事件独立，只需每项代表正确的条件概率；若只是四个边际准确率，则不能直接相乘。

> **要点**：本讲不进行实验，但建议未来读论文时特别关注：同一方法提升了什么指标？是否同时增加管理成本？是否保留了可信历史和错误修正的可验证路径？

## 十二个常见误区：通过反例巩固主线

1. **误区1：新消息总应覆盖旧消息。** 真实变化与认知纠错不同；历史事件应可追溯。
2. **误区2：时间最新的信息总正确。** 来源身份、范围和有效时点同样重要。
3. **误区3：相似度高就可以合并。** 同义而否定相反的主张不能合并成事实。
4. **误区4：重复说三次就更可靠。** 循环转述可能只有一个源头。
5. **误区5：遗忘曲线能判断真假。** 它只能成为一种优先级或强化策略的启发。
6. **误区6：检索降权等于删除。** 索引和原始记录可能仍存在。
7. **误区7：状态失效等于事件从未发生。** 当前有效性与历史可追溯性不同。
8. **误区8：主表删除就完成了清理。** 还需要处理派生索引、缓存等副本。
9. **误区9：同步索引是零成本、瞬时的。** 实际存在异步更新与版本滞后。
10. **误区10：哈希相同证明事实可信。** 哈希只能帮助校验字节未变化。
11. **误区11：模型愿意UPDATE就能改变权限。** 权限要由适当的主体与执行控制系统确认。
12. **误区12：问答准确率足以评价记忆。** 更新一致性、删除语义、错误传播和整体成本同样关键。

**图18：本讲必须牢牢记住的认识边界**（PDF原理图；文字版保留其对应机制与文字解说。）

> **要点**：判断一条记忆时，至少问四次：**谁说的、说的是什么、什么时候和在哪个范围内有效、它现在被怎样维护？**

## 理论思考题（1—6）

以下题目全部是理论练习，不需要安装软件、运行代码或开展实际实验。建议先不看后面的答案，用一张纸写出每一步的因果关系。

- **第1题·定义题：**同一条记忆经历了“降权、失效、删除”，分别改变什么？
- **第2题·分类题：**用户确认了新偏好；另一个AI提出新建议；一段工具日志重复上传。三条分别如何进入记忆写入决策？
- **第3题·双时间题：**D09出现504，D18才查证原因。回答“D10系统知道什么”和“今天回看D09是什么原因”，能否使用同一句回答？

## 理论思考题（7—12）

- **第7题·空间题：**每天80条，90天，每条原文300B、另存768维float32向量，估计原文和纯向量各自占多少字节？
- **第8题·删除题：**用户请求删除某条个人信息。系统只删主数据库记录却仍能从向量检索中找回。说明缺少的步骤。
- **第9题·并发题：**两个Agent都依据v5更新，同一个版本只能接受一个提交；第二个应采取什么动作？
- **第10题·评估题：**四个条件成功率0.95、0.90、0.92、0.90，联合概率是多少？如果它们只是边际成功率，这样乘对吗？
- **第11题·归因题：**权威状态v12，向量索引v10，用户询问最新许可。系统回答旧许可，究竟是“记忆没写入”还是“读取/使用过程失效”？
- **第12题·独立重建：**画出至少包含事件记录、当前状态、检索索引、缓存、控制器的动态记忆架构，并说出更正或删除应如何传播。

> **常见误区 / 风险**：遇到“不能收费”或“删除个人资料”的例子时，不要只考虑模型的语义相似度；应同时判断权限边界和数据生命周期。

> **要点**：第10题问的是条件概率链式法则；第11题要求分层归因，不能把所有错误都称为“模型忘记了”。

## 逐题解析（1—6）

#### 1—3：操作、来源与时间

**第1题：**降权改变未来搜索/排序机会，事实未必失效；失效改变当前视图是否采用该主张，历史可能保留；删除涉及被授权范围内的权威与派生存储清理。

**第2题：**新偏好属于待核的主体相关信息，经确认可新增或更新；AI建议只能标记提议，不能冒充授权；重复日志应按原始事件ID去重或引用。

**第3题：**不能。D10的系统知识不含D18才查明的原因；“今天回看”可以带来源说明后来查明的结论。这对应事务/记录时间与事件时间的区别。

#### 4—6：作用域、证据独立性与衰减

**第4题：**P当前暂停保持有效；Q一次性例外仅适用于Q。D30无法把Q许可转成P许可。需要核对是否存在更新的P项目授权。

**第5题：**若B/C只是衍生转述，则通常只有A提供的一份源头证据；且A的说法本身仍需核验真实性与权限。

**第6题：**R(28)=2^(-28/14)=1/4=0.25；R(42)=1/8=0.125。它是检索权重教学函数，不是法律效力、事实有效期或授权到期判据。

> **要点**：关键不是背出答案，而是能解释为什么另一个看似合理的回答是不成立的。

## 逐题解析（7—12）

**第7题：**条数80×90=7200；原文7200×300=2,160,000B；向量7200×768×4=22,118,400B。真实占用还需加索引、元数据等。

**第8题：**需按请求范围查找向量索引、全文索引、图关系、缓存、摘要、相关副本并执行传播或失效处理；禁止因主表已删便声称所有副本已删。

**第9题：**第二个提交发现预期版本与最新版本不符，应重新读取v6、识别是否与自己意图冲突，并按有授权的规则重算后重试或提交待决状态。

**第10题：**若四项依次是适当的条件成功率，则联合概率=0.95×0.90×0.92×0.90=0.70794≈70.79%；若只是边际概率，直接相乘缺乏依据。

**第11题：**权威v12已经保存，所以不应断言“没写入”。故障更可能在索引版本、候选回源、时间/状态核验或控制执行环节；需核验原始轨迹定位。

**第12题：**参考架构：事件日志→当前状态；当前状态产生带版本的派生索引/缓存；模型按需检索并回源；控制器另核授权。更正更新历史与有效视图，删除按范围撤销缓存及各副本并核验状态。

> **要点**：第7题检查单位，第9题检查是否有静默覆盖，第10题检查是否是条件概率，第11题检查是否先排除已保存成功的层次。
